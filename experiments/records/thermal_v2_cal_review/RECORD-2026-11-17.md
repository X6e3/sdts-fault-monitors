## 2. Mathematical facts (MATH)

- **M1 — machine TUTARSIZ is sound.** A[k] (the ambient response) satisfies:
  - |A[k] − A[k−1]| ≤ ρ_A, because the TA→A impulse response is nonnegative and sums to 1, and
    (e) gives ΔA[1] = 0;
  - A[k] ∈ [23, 27], as a convex combination.

  The interval recursion uses only these, so it is a relaxation of the oracle's set. If it is empty, the
  oracle's set is empty.
- **M2 — the machine offset outer bound is sound.** Every constant offset that explains the data lies inside
  it. So TUTARLI(R) implies the oracle's exact offset interval ⊆ [−R, R]: the second clause of P3 holds
  structurally.
- **M3.** With (b): 2d ≥ |z[k] − z[k−1]| − ρ_A for any explaining path (M1's rate property plus two noise
  terms).
- **M4.** d* is nondecreasing in the prefix length. A certified consistent prefix of length t and a
  certified inconsistent prefix of length t+1 fix t* = t, whatever earlier probes returned.
- **M5.** Any method that sees only z gives the same verdict under E0 and E1 for additive faults
  (Proposition 1). P2 is therefore an implementation check.
- **M6.** Healthy runs satisfy (a)–(e) by construction, so d* ≤ δ is guaranteed.
  - V0 400/400 consistent is a numerical check of the oracle (max d_up 0.299398, margin 6e-4 °C).
  - It is not evidence for SDTS or for the representation question.

## 3. Counterexample: TUTARLI is a statement about constant offsets, not about sensor error

- **CAL.** Machine TUTARLI at R=1 occurs on 0/400 healthy runs and on 100/400 drift_0.001 runs.
  - On those runs the true sensor error at the end is 3.005–3.282 °C, above R=1, and also above R=3 in the
    R=3 verdicts on the same runs.
  - The oracle agrees that the data are consistent (28/28 on the 50-seed overlap).
- **Worked case, 410000/E0 (test `test_consistent_bounds_constant_offsets_not_sensor_error`).**
  - True ambient: 23.19–23.30 °C.
  - Drift 0.001 °C/s from t_f = 475.
  - Machine outer offset interval: (−0.607, 0.202). Verdict TUTARLI at R=1 and R=3.
  - True error at the end: +3.124 °C.
- **Mechanism (MATH).**
  - A drift the ambient rate can follow is an ambient twin while the box lasts (Proposition 4, without
    (c)).
  - The twin's ambient sweeps the box, which is exactly what Proposition 2 needs for certification. The
    drift therefore produces the certificate.
  - The same run without drift has offset interval [−3.71, 0.20] and is not certifiable.
- **Consequence.**
  - P3 holds.
  - The wording in section 6, "it states exactly when its absolute accuracy can not be certified", is true
    only inside the constant-offset fault class.
  - Any write-up must state TUTARLI(R) as "every constant-offset explanation has |b| ≤ R".
- The protocol text is not changed (frozen).

## 5. The machine — function and guarantees

- **Function.** Online and O(1) state:
  - the model S driven by the known command;
  - two interval recursions on A (with and without the box);
  - a running offset intersection.

  It is a standard set-membership (interval) filter. No novelty is claimed.
- **Guaranteed (MATH, under (a)–(e) and exact plant parameters):**
  - TUTARSIZ is sound (M1);
  - the offset outer bound is sound (M2);
  - E0/E1 identity for additive faults (M5).
- **Not guaranteed:**
  - Completeness or latency. On CAL it misses 0 oracle inconsistencies at full-run level, but lags up to
    963 s. This is the cost of dropping the filter smoothness (s). There is no proof.
  - Any statement about non-constant faults (section 3).
  - Robustness to plant-parameter error (out of scope, v2).
- **AYIRT EDİLEMEZ at R=1 on all 400 healthy runs (CAL).** The generator's ambient is a random walk with an
  expected range of about 0.11 °C per run. Proposition 2 needs a 2 °C sweep.

## 6. Baselines and TRAIN — blocked on parameters the frozen text does not fix (OPEN)

The harness (`91bda17`) is in place:
- the DMREDA core is byte-identical to the preregistered file (sha256 `0b8bffc7…`);
- CUSUM is two-sided on Δy;
- evaluation starts at sample 300.

The protocol says "maximum statistic plus 5 %" but leaves three choices open. Each one decides P8:

1. **CUSUM allowance a.** With a = 0, the statistic is y − (running min) and its mirror: a range detector.
   With a = ρ_A, it is the two-point test y[k] − y[j] − ρ_A(k − j), a model-free form of (b).
2. **Thresholds per arm or pooled.** Under E1, y swings by tens of °C with the command. A pooled threshold
   would be set by E1 and blind E0.
3. **The DMREDA scalar.** Sol uses the fast-gate ratio max(d/th_d, g/th_g). DMREDA's confirmation stage
   is not used, and the native alarm is binary. Scaling th_d/th_g would alter the core.

These must be fixed in a dated addendum before any TRAIN data are generated. Expected direction (HYP,
analytic, nothing run):
- with a = 0 and per-arm thresholds, E0 drifts of 0.0005–0.002 °C/s accumulate 1.5–6.6 °C. That is far above
  a healthy E0 range of about 2δ + 0.1 °C, so P8 would likely fail for CUSUM on E0;
- with a = ρ_A, P8 would likely hold for drifts below ρ_A;
- with pooled thresholds, P8 would hold trivially.

**Same-conditions caveat (MATH plus the generator's law):**
- Thresholds set on TRAIN healthy runs learn the generator's ambient law, whose range is about 40× tighter
  than what (b) allows over a run.
- The machine and the oracle use only the worst case in (b).
- P8 therefore measures, in part, the gap between assumption (b) and the generator's ambient law, not own
  history against a model under identical information.
